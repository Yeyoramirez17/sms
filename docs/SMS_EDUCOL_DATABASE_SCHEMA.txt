================================================================================
ESPECIFICACIÓN DEL ESQUEMA DE BASE DE DATOS
SMS-EDUCOL - Sistema de Gestión Escolar
Base de Datos: PostgreSQL 16.x
================================================================================

CONVENCIONES GENERALES:
- Nomenclatura: snake_case para tablas y columnas
- Claves primarias: id (tipo BIGSERIAL)
- Timestamps: created_at, updated_at (TIMESTAMP NOT NULL)
- Soft deletes: deleted_at (TIMESTAMP NULL) donde aplique
- Claves foráneas: nombre_tabla_singular_id
- Índices: Se crean automáticamente en PKs y FKs, adicionales según se especifique

================================================================================
TABLA: users
================================================================================
Propósito: Almacena credenciales de autenticación de todos los usuarios del sistema

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY
email               VARCHAR(255)    NOT NULL UNIQUE
password            VARCHAR(255)    NOT NULL (hash bcrypt)
role                VARCHAR(50)     NOT NULL (valores: 'superadministrator', 'administrator', 'teacher', 'student')
userable_type       VARCHAR(255)    NOT NULL (valores: 'App\Models\Student', 'App\Models\Teacher')
userable_id         BIGINT          NOT NULL
remember_token      VARCHAR(100)    NULL
email_verified_at   TIMESTAMP       NULL
created_at          TIMESTAMP       NOT NULL
updated_at          TIMESTAMP       NOT NULL
deleted_at          TIMESTAMP       NULL

Restricciones:
--------------
- UNIQUE(email)
- CHECK(role IN ('superadministrator', 'administrator', 'teacher', 'student'))
- INDEX en (userable_type, userable_id) para búsquedas polimórficas

Relaciones:
-----------
- Relación polimórfica con students y teachers mediante userable_type y userable_id

TABLA: academic_periods
================================================================================
Propósito: Períodos académicos (bimestres, trimestres, semestres)

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY

name                VARCHAR(100)    NOT NULL (ej: '1er Bimestre', 'Primer Trimestre')
start_date          DATE            NOT NULL

- UNIQUE(academic_year_id, order_number)
- Las fechas deben estar dentro del rango del año lectivo
- INDEX en academic_year_id
- INDEX en order_number

Relaciones:
-----------
- Pertenece a academic_year (many-to-one)
- Tiene muchos grade_records (one-to-many)

================================================================================
TABLA: groups
================================================================================
Propósito: Grupos de estudiantes dentro de cada grado

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY
grade_id            BIGINT          NOT NULL
academic_year_id    BIGINT          NOT NULL
name                VARCHAR(50)     NOT NULL (ej: 'A', 'B', 'C', '1', '2')
max_students        INTEGER         NOT NULL DEFAULT 40
teacher_id          BIGINT          NULL (director de grupo, opcional)
shift               VARCHAR(50)     NULL (valores: 'Mañana', 'Tarde', 'Completa', 'Nocturna', 'Fin de semana')
classroom           VARCHAR(100)    NULL
description         TEXT            NULL
created_at          TIMESTAMP       NOT NULL
updated_at          TIMESTAMP       NOT NULL
deleted_at          TIMESTAMP       NULL

Restricciones:
--------------
- FOREIGN KEY(grade_id) REFERENCES grades(id) ON DELETE RESTRICT
- FOREIGN KEY(academic_year_id) REFERENCES academic_years(id) ON DELETE CASCADE
- FOREIGN KEY(teacher_id) REFERENCES teachers(id) ON DELETE SET NULL
- UNIQUE(grade_id, academic_year_id, name)
- CHECK(max_students > 0)
- CHECK(shift IN ('Mañana', 'Tarde', 'Completa', 'Nocturna', 'Fin de semana'))
- INDEX en grade_id
- INDEX en academic_year_id
- INDEX en teacher_id

Relaciones:
-----------
- Pertenece a grade (many-to-one)
- Pertenece a academic_year (many-to-one)
- Pertenece a teacher como director (many-to-one, opcional)
- Tiene muchos enrollments (one-to-many)
- Tiene muchos assignments (one-to-many)

TABLA: enrollments
================================================================================
Propósito: Matrículas de estudiantes en grupos

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY
student_id          BIGINT          NOT NULL
group_id            BIGINT          NOT NULL
academic_year_id    BIGINT          NOT NULL
enrollment_number   VARCHAR(50)     NOT NULL UNIQUE (auto-generado)
enrollment_date     DATE            NOT NULL
status              VARCHAR(50)     NOT NULL DEFAULT 'active' (valores: 'active', 'withdrawn', 'transferred')
withdrawal_date     DATE            NULL
withdrawal_reason   TEXT            NULL
notes               TEXT            NULL
created_at          TIMESTAMP       NOT NULL
updated_at          TIMESTAMP       NOT NULL
deleted_at          TIMESTAMP       NULL

Restricciones:
--------------
- FOREIGN KEY(student_id) REFERENCES students(id) ON DELETE RESTRICT
- FOREIGN KEY(group_id) REFERENCES groups(id) ON DELETE RESTRICT
- FOREIGN KEY(academic_year_id) REFERENCES academic_years(id) ON DELETE CASCADE
- UNIQUE(enrollment_number)
- UNIQUE(student_id, academic_year_id) - Un estudiante solo puede tener una matrícula activa por año
- CHECK(status IN ('active', 'withdrawn', 'transferred'))
- CHECK(withdrawal_date IS NULL OR withdrawal_date >= enrollment_date)
- INDEX en student_id
- INDEX en group_id
- INDEX en academic_year_id
- INDEX en status
- INDEX compuesto en (academic_year_id, status) para consultas de matriculados activos

Relaciones:
-----------
- Pertenece a student (many-to-one)
- Pertenece a group (many-to-one)
- Pertenece a academic_year (many-to-one)
- Tiene muchos grade_records (one-to-many)

Notas:
------
Validar en lógica de aplicación que al crear matrícula, el grupo no exceda max_students

TABLA: attendances
================================================================================
Propósito: Registro de asistencia diaria por asignatura

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY
assignment_id       BIGINT          NOT NULL
student_id          BIGINT          NOT NULL
date                DATE            NOT NULL
status              VARCHAR(50)     NOT NULL (valores: 'present', 'absent', 'late', 'excused')
notes               TEXT            NULL
created_at          TIMESTAMP       NOT NULL
updated_at          TIMESTAMP       NOT NULL

Restricciones:
--------------
- FOREIGN KEY(assignment_id) REFERENCES assignments(id) ON DELETE CASCADE
- FOREIGN KEY(student_id) REFERENCES students(id) ON DELETE CASCADE
- UNIQUE(assignment_id, student_id, date) - Un registro de asistencia por estudiante/asignatura/fecha
- CHECK(status IN ('present', 'absent', 'late', 'excused'))
- CHECK(date <= CURRENT_DATE) - No se puede registrar asistencia futura
- INDEX en assignment_id
- INDEX en student_id
- INDEX en date
- INDEX compuesto en (assignment_id, date) para consultas de asistencia del día
- INDEX compuesto en (student_id, date) para historial del estudiante

Relaciones:
-----------
- Pertenece a assignment (many-to-one)
- Pertenece a student (many-to-one)

- INDEX en subject_id
- INDEX en is_active

Relaciones:
-----------
- Pertenece a subject (many-to-one, opcional)
- Tiene muchos grade_records (one-to-many)

Notas:
------
Validar en lógica de aplicación que la suma de weight_percentage por asignatura = 100

================================================================================
TABLA: grade_records
================================================================================
Propósito: Registros individuales de calificaciones

Columnas:
---------
id                  BIGSERIAL       PRIMARY KEY
enrollment_id       BIGINT          NOT NULL
subject_id          BIGINT          NOT NULL
academic_period_id  BIGINT          NOT NULL
evaluation_type_id  BIGINT          NOT NULL
score               DECIMAL(5,2)    NOT NULL (soporta decimales para escala 1.0-5.0)
evaluation_date     DATE            NOT NULL
teacher_id          BIGINT          NOT NULL (quien registra)
notes               TEXT            NULL
created_at          TIMESTAMP       NOT NULL
updated_at          TIMESTAMP       NOT NULL
deleted_at          TIMESTAMP       NULL

Restricciones:
--------------
- FOREIGN KEY(enrollment_id) REFERENCES enrollments(id) ON DELETE CASCADE
- FOREIGN KEY(subject_id) REFERENCES subjects(id) ON DELETE RESTRICT
- FOREIGN KEY(academic_period_id) REFERENCES academic_periods(id) ON DELETE RESTRICT
- FOREIGN KEY(evaluation_type_id) REFERENCES evaluation_types(id) ON DELETE RESTRICT
- FOREIGN KEY(teacher_id) REFERENCES teachers(id) ON DELETE RESTRICT
- CHECK(score >= 0 AND score <= 100) - Ajustar según sistema de calificación institucional
- INDEX en enrollment_id
- INDEX en subject_id
- INDEX en academic_period_id
- INDEX en evaluation_type_id
- INDEX compuesto en (enrollment_id, subject_id, academic_period_id) para consultas de boletines

Relaciones:
-----------
- Pertenece a enrollment (many-to-one)
- Pertenece a subject (many-to-one)
- Pertenece a academic_period (many-to-one)
- Pertenece a evaluation_type (many-to-one)
- Pertenece a teacher (many-to-one)

Notas:
------
Para cálculo de promedios:
- Promedio por asignatura/período: AVG de scores ponderado por weight_percentage
- Promedio general del período: AVG de promedios de todas las asignaturas
- Promedio final anual: AVG de promedios de todos los períodos

AUDITORÍA (Opcional pero recomendado):
---------------------------------------
Tabla: audits
- Registrar acciones críticas (CREATE, UPDATE, DELETE) en:
  * students
  * teachers
  * enrollments
  * grade_records
  * users

Columnas sugeridas:
- id (BIGSERIAL PRIMARY KEY)
- user_id (BIGINT) - quien realizó la acción
- auditable_type (VARCHAR) - tipo de modelo afectado
- auditable_id (BIGINT) - ID del registro afectado
- event (VARCHAR) - tipo de evento (created, updated, deleted)
- old_values (JSONB) - valores anteriores
- new_values (JSONB) - valores nuevos
- ip_address (VARCHAR)
- user_agent (TEXT)
- created_at (TIMESTAMP)

SECUENCIAS PARA CÓDIGOS AUTO-GENERADOS:
----------------------------------------
- student_code: SEQ_STUDENT_CODE (formato: EST-YYYY-NNNN)
- employee_code: SEQ_EMPLOYEE_CODE (formato: DOC-YYYY-NNNN)
- enrollment_number: SEQ_ENROLLMENT (formato: MAT-YYYY-NNNNNN)

Implementar mediante funciones/triggers de PostgreSQL o lógica de aplicación

VISTAS ÚTILES (Opcional):
--------------------------
1. view_active_enrollments: Matrículas activas con datos de estudiante y grupo
2. view_student_grades_summary: Resumen de calificaciones por estudiante
3. view_teacher_schedule: Horario de carga académica por docente
4. view_attendance_statistics: Estadísticas de asistencia por estudiante/grupo

PARTICIONAMIENTO (Para instituciones grandes):
-----------------------------------------------
Considerar particionar las tablas:
- attendances: Por año (date)
- grade_records: Por año lectivo (academic_year_id)

POLÍTICAS DE RESPALDO:
----------------------
- Respaldo completo: Diario
- Respaldo incremental: Cada 6 horas
- Retención: Mínimo 30 días

ÍNDICES FULL-TEXT (PostgreSQL):
--------------------------------
Para búsquedas de texto completo en:
- students(first_name, last_name)
- teachers(first_name, last_name)
- subjects(name, description)

Ejemplo: CREATE INDEX idx_students_fulltext ON students USING gin(to_tsvector('spanish', first_name || ' ' || last_name));
